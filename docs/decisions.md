# Decision register

The full register: every decision, with its rationale. `STATUS.md` keeps a one-line index of
these and is the entry point; this file is where a decision is read in full, and the `docs/adr/`
record named in a rationale is where it is read in depth.

Why this file exists separately: the register was 45% of `STATUS.md`, and roughly half of it
restated an ADR that already owned the decision. Splitting keeps `STATUS.md` readable as status
without losing the rationale for decisions that have no ADR of their own (D1-D6, D21, D26).

D1–D6 from the first research pass, D7–D14 from the pre-spike design session, D15–D18 forced
by phase 0's findings, D19 from the pre-phase-1 design session, D20 from the corpus analysis,
D21 from phase 2's persistence design, D22–D24 from phase 3's design (ADR 0004), D25 forced by
phase 3's live run, D26 from phase 4's transport question, and **D27–D33 from the 2026-09-15 POC design session (ADR 0005), D34 from phase 5's live leg
(ADR 0007).**

| D19 | **Workflow authoring surface: `defineWorkflow(id, {input, output?, agent?, run})` with a six-member `ctx` (`dir`, `agent`, `exec`, `assert`, `log`, `writeBack`).** Ownership rule: the runtime owns the tree, the log, and cancellation; the workflow owns everything else. `ctx.assert` records a callback's outcome as a typed event but never throws; `ctx.log` is the generic escape hatch.                                                                                                   | ADR 0002, designed against the spike's proven seam. | D20 | **D3's event type: a typed Factory spine with harness chunks carried opaquely in AG-UI form.** `RunEvent = {runId, seq, ts, payload}`; 13 payload tags covering ADR 0002's emission surface, plus one `AgentChunk` member holding the chunk verbatim as `Schema.Json`. **`seq` — Factory-assigned, monotonic — is the only ordering key. Termination always carries an explicit outcome (`completed`/`failed`/`cancelled`). Correlation is by runtime-assigned `stepId`/`execId`, never by name.** | ADR 0003, designed against the nine corpora. Opaque because these chunks are AG-UI, a published cross-vendor protocol whose transport (SSE, NDJSON, resumable offsets) and client TanStack already ships — enumerating opencode's 16 types would break on the planned `claudeCodeText` comparison and buy nothing. The other three clauses are forced by measurement, not taste: chunk timestamps invert by up to 1473 ms because `sandbox.file` carries an mtime; cancellation emits no chunk whatsoever; and step names are not unique, so 0a-2's `{step, chunk}` envelope does not generalise.         |
| D21 | **Persist the event log with plain synchronous functions over `bun:sqlite` (not `@effect/sql-sqlite-bun`, not installed), in a single `events` table** (`run_id, seq, ts, tag, payload`, PK `(run_id, seq)`) — no separate `runs`/`steps`/`artifacts` tables.                                                                                                                                                                                                                                      | D4 scopes "Effect owns the server" to phase 3's daemon; phase 2 is still CLI-driven, so wrapping synchronous in-process sqlite I/O in Effect here would add a layer with nothing to bridge — matches `ctx.exec`/`ctx.writeBack` staying plain async functions. A run's identity, outcome and timing are all derivable from its own event rows (`RunStarted`, and the terminal event or its absence), so a second table would only be a cache that can drift from the log it caches. `"interrupted"` status is derived at read time, not written at crash time — nothing observes the crash as it happens. |

| D23 | **`ReadySource`: a two-method pluggable interface** (`listReady`/`claim`), ported from the wayful script's GraphQL query + `gh project item-edit` claim, with the same soft/hard blocker distinction.                                                                                                                                                                                                                                                                                             | ADR 0004. `makeGitHubProjectsSource` is the only real implementation today; `makeFakeReadySource` backs `dispatch.test.ts`/`integration.test.ts`. A failed claim is "lost the race, skip", not an error.                                                                                                                                                                                                                                                                                                                                                                                              |
| D24 | **No separate retry-state file.** Backoff is derived at reconcile time from the sqlite event log (`RunStarted.input.issueNumber` as the join key), doubling per consecutive failure. WIP limit of 1 is enforced via the current process's in-memory active-run registry, not sqlite. Per-issue backoff, not the wayful script's global pause-on-any-failure.                                                                                                                                    | ADR 0004. Nothing to keep in sync with the log it would cache. D12's "interrupted ≠ active" applies to dispatch too: a dead process's run doesn't block new dispatch after a restart. Global pause doesn't fit Factory — workflows are one-shot (D19), so a retry is always a fresh run, and global pause would starve unrelated issues for no offsetting benefit.                                                                                                                                                                                                                                  |
| D25 | **`porcelainPaths` (`src/lib/writeback.ts`) always passes `--untracked-files=all` to `git status --porcelain`.** | Found by phase 3's live dispatch run, not by any prior test: plain `--porcelain` collapses a wholly-new untracked directory into one `?? dir/` line instead of listing files inside it, which let a nested D16 marker slip past `isStrayPath` and ship into a real PR (factory-spike#5). `docs/findings/6-live-dispatch-run.md`, `src/lib/writeback.test.ts`. |
| D26 | **Live data reaches the SPA by polling the runs list and per-run SSE for run detail.** A single multiplexed WebSocket for the whole app is deferred, not rejected. SSE frames gain `id: ${seq}` and the handler honours `Last-Event-ID` so a reconnect resumes instead of replaying. The client keeps one `subscribeToRun(runId, sinceSeq, onEvent)` seam, so swapping transport later is one file. | **The transcript is not a separate stream** — `AgentChunk` is a `RunEventPayload` member sharing the same `seq` space (ADR 0003), so there is nothing to multiplex it *with*. The only multiplexing available is across runs, and D24 pins WIP to 1: at most one run is live today, so the saved connections pay for concurrency that does not exist yet. What a WebSocket would genuinely buy — resumable reconnect — `seq` + `Last-Event-ID` buys for about five lines. Against that, a WS rewrite must reproduce `sseStream`'s subscribe-before-read → buffer → dedupe-by-`seq` ordering (`http.ts:51-94`) per *dynamic* subscription, which is the subtlest thing phase 3 built. Revisit on the trigger in Deferred. **Amended by D29:** the "WIP is 1" clause no longer holds, but the conclusion does — the SPA opens SSE only on run detail, which shows one run, so concurrent runs still do not mean concurrent connections. See the revised trigger in Deferred. |
| D27 | **`factory.config.ts` is the project's entry point**, a TypeScript module carrying the run environment (`repo` — ssh url, identity, base branch, slug — `workspaceRoot`, `maxConcurrentRuns`) **and the workflow list, imported directly**. One repo per daemon for the POC. | ADR 0005. Collapses D5's hardest constraint: "enumerate and validate workflows without executing arbitrary files" only existed because the daemon was going to scan a directory, and importing a config module is the operator's own explicit act. The registry is that array. Also moves `repoSlug`/`baseBranch` out of workflow input — they are properties of the deployment, and the runtime already owns the tree (D8). Flags were the alternative (`--dispatch-*`'s precedent) and do not fit: the workflow list is not expressible as one. |
| D28 | **One working tree per run** (`<workspaceRoot>/<runId>/`), cloned from a **local bare mirror** refreshed on allocation. Last N workspaces retained, evicted oldest-first. | ADR 0005. **This is the whole of concurrency.** The sandbox (`threadId: options.runId`, `run.ts:159` + D10), exec cwd, the `active` registry (`runs.ts:16`), SSE fan-out and sqlite (WAL) are *already* per-run; the only shared resource is the directory `resetClone` wipes (`clone.ts:27`). So the deferred "N sandboxes with one worktree each" framing was pessimistic — it predates D10's validation. Mirror over fresh network clone because the latency is paid on every click of a manual start button. Retention because the moment a tree is worth inspecting is the moment a run failed. |
| D29 | **One `maxConcurrentRuns` in config, enforced by a single admission function** shared by the HTTP API and the dispatcher. 409 over the limit. **Queued runs deferred, with the seam built for them.** | ADR 0005. There is no limit today: `daemon.ts:94` injects `hasActiveRun: () => activeRunIds().length > 0` — a *boolean* — and `POST /api/runs` checks nothing at all, so manual starts have always bypassed D24's WIP limit. A queue is wanted (it is what makes scheduling ahead possible) but needs a `RunQueued` event touching ADR 0003, restart survival, ordering and cancel-before-start — a second scheduler beside the dispatcher, and deciding it before the POC is in anyone's hands is deciding it blind. Admission is one explicit function so a queue is later a swap, not a redesign. |
| D30 | **`GET /api/workflows` serves the config's array**, each workflow's `id` plus its input schema as JSON Schema. | ADR 0005. Reuses the conversion already performed at `ctx.agent`'s `outputSchema` boundary. No filesystem scan (D27). |
| D31 | **`POST /api/runs {workflowId, input}`; `factory start` is a thin HTTP client.** Input decoded through the workflow's own `Schema` (400 on failure, 409 over the limit). `factory run` **retained** as the no-daemon path. | ADR 0005. The server supplies `dir`/clone/identity from config; the caller supplies only what is task-specific. `factory start` must not be a second in-process runner: `factory run` opens its own sqlite connection, so a daemon would not see that run in its in-memory registry and neither cancel nor D29's limit would apply. The path-based body stays internally for the dispatcher, which supplies real paths legitimately. |
| D32 | **Write-back metadata is agent-supplied, branch included** (widens D11); `repoSlug`/`baseBranch` leave the `ctx.writeBack` signature (D27). **The runtime resolves branch collisions reactively** — push, and only on rejection (or a `gh pr create` conflict) suffix with a short `runId`, re-branch and retry once, returning the branch actually used. | ADR 0005. D11's argument — Factory stays out of the business of knowing what a PR should say — applies to the branch name too; stopping at title/body was arbitrary, and hardcoding a branch is what forces a workflow-per-task. Always-suffixing is wrong because agent-generated names differ per task, so collisions are the rare case and an unconditional hex fragment uglifies every name. Pre-checking is wrong because it races: two concurrent runs both ask "does `feat/x` exist?", both see no, both push. The check races; the push does not, and `writeBack` already inspects exit codes (`writeback.ts:135`). |
| D34 | **The in-sandbox `opencode serve` gets a fresh free port per `stream()` call** — no shared constant, no allocation registry. Scoped to D7's local-process sandbox; a published-ports docker path must revisit. | ADR 0007. Found live in phase 5 P6's concurrency leg (finding 11): the adapter's `DEFAULT_PORT` (4096) is a constant, so under `localProcessSandbox` two runs' servers race to bind the same host port and the later one exits before readiness — deterministic, invisible to every fake. The OS's ephemeral allocator is the shortest honest fix. |
| D33 | **The start form is single-depth** — `string`/`number`/`boolean` fields from the input schema — **with a raw-JSON escape hatch** validated by D31's decode. | ADR 0005. Sufficient rather than a compromise because D27 and D32 shrink `implement-issue`'s input from four fields (three of them environment config retyped on every start) to `{ issueNumber }`. |

| D35 | **The public API is one barrel, `src/index.ts`, declared by an `exports` map** — the authoring surface (`defineWorkflow`, `defineConfig`, `Schema`, `isTerminal`, the `DEFAULT_*` constants and the types a workflow body touches) and nothing else. Deep imports into `runtime/`, `server/`, `persistence/` and `web/` are unreachable. The root manifest is renamed `@frebreco/factory` (still `private`) so in-repo code — `sample/`, the tests — **imports through the same specifier a user types**, resolving by self-reference. `workflows/` stops shipping. | ADR 0008. Phase 5 left the POC usable only from inside this repo: everything a user would write imported relative paths into `src/`, and `src/index.ts` still exported phase 0's `slugify`. The self-reference clause is the load-bearing one — with it, the published entry point cannot drift from the tested one, because they are the same import. `workflows/implement-issue.ts` imports `src/lib/tree-snapshot`, an internal the barrel does not export, so shipping it would advertise a path users must not depend on; `factory init` generates a workflow instead. |
| D36 | **`.factory/` is the project folder, holding authored source (`factory.config.ts`, `workflows/`) as well as regenerable state (`factory.db`, `workspaces/`)**, with `factory init` scaffolding the former and writing a `.gitignore` that ignores the latter *by name*. Config discovery is ordered — `.factory/factory.config.ts`, then the root `factory.config.ts` — and `factory serve` needs no `--config`. | ADR 0008. Widens D27: the entry point's *content* is unchanged, only where it is found. The root fallback keeps phase 5's `sample/` working untouched and makes it the fallback's regression test. `init` explicitly strips a pre-existing blanket `.factory/` ignore line, which would otherwise silently swallow the config it just wrote — the one case where scaffolding must mutate a file the user owns. `init` never overwrites without `--force`, and fills the `repo` block from the checkout's `origin`/identity/default branch, degrading to flagged placeholders outside a git repo. |
